ML-KEM Decapsulation Failure-Mode Assessment

Audit of ML-KEM encapsulation and decapsulation failure modes across ML-KEM-512/768/1024: implicit rejection, decapsulation-failure oracles, malformed inputs, corrupted keys, comparison traps, and hybrid classical-plus-ML-KEM combiner behaviour. Tested with local fixtures only against three independent implementations (pyca/cryptography, liboqs, and a pure-Python FIPS 203 implementation written from the standard). No live-network testing, no mutation of the pinned tree.

Pinned tree: postfiatd 0085a1ff885d6a446369cf73a4430f75af22be55.

Headline finding. The pinned tree contains no ML-KEM code at all (F-01): there is no ML-KEM attack surface in-tree — and no ML-KEM capability either. Every other failure mode below was confirmed against reference implementations and applies to a future integration. No Critical or High finding.
