```sh
git clone <repo-url> mlkem-repro
cd mlkem-repro
bash run_all.sh
```

The full fresh-clone run log is `results/reproduction_log.txt`.

## What `bash run_all.sh` does

1. Resolves Python: uses `.venv/bin/python3` if present, else the system
   `python3` if it already imports `cryptography...mlkem` and `oqs`, else
   creates `.venv` and installs the pinned `requirements.txt` (network
   needed once: `cryptography==50.0.2`, `liboqs-python==0.16.0.2`).
2. Runs `scripts/run_checks.py` (34 checks, ~17 s), capturing the log outside
   the pack first, then copying it to `results/run_log.txt`.
3. Runs `scripts/verify_constants.py` (FIPS 203 Table 2 vs implementation
   and ACVP vector lengths) and saves the output to
   `results/constants_verification.txt`.
4. Runs `scripts/build_derived.py`, regenerating `docs/index.html` from the
   finished run outputs.
5. Copies the run log, summaries, and per-check outputs to
   `results/outputs/` (the clean-setup copies).
6. Regenerates `results/SHA256SUMS` and runs `bash verify_digests.sh --check`,
   saving the output to `results/digest_check_output.txt`.

Expected final state: exit 0, `results/SHA256SUMS` verifies with all files
OK, `git status` clean (the `.venv/` directory is git-ignored and excluded
from the digest manifest).

## Single-step checks

```sh
python3 scripts/run_checks.py        # harness only; log goes to stdout
python3 scripts/verify_constants.py # constants only
bash verify_digests.sh --check       # digest verification only
```

## Determinism note

All random inputs in the harness come from `random.Random(20261115)`, so the
run log is byte-identical across runs on the same machine. The only
non-deterministic inputs are liboqs keypairs (OS randomness); the harness
logs only booleans and lengths for those cases, never raw key material.
`results/env.txt` records the interpreter and library versions.
